# Operations runbook

## Job lifecycle

The API creates an immutable job specification, reserves credits, and sends an SQS message. A worker claims `queued`, records every stage in `job_events`, uploads an output, and finalizes the reservation only after output creation. Provider or infrastructure failures set an explicit error code and release the reservation; user cancellation is accounted as consumed work. Jobs can be retried only through a deliberate operator action; the worker never silently retries a failed model call in-process.

## Production checks

- Run `PYTHONPATH=. python scripts/production_readiness.py` from the repository root before enabling public processing. It fails closed unless PostgreSQL/S3/SQS, secure cookies, measured pricing, exact model-release evidence, an eligible GPU profile, verified mail, and complete Stripe configuration are present; it never prints secret values. Keep `config/model_release_manifest.json` outside git or populate it from the checked-in example only after the exact checkpoint and dependency review is complete.

- Set PostgreSQL, S3, SQS, `COOKIE_SECURE=true`, and a non-local `FRONTEND_ORIGIN`.
- Set `MAIL_PROVIDER=smtp` plus `MAIL_FROM` and SMTP credentials, or `MAIL_PROVIDER=ses` with a verified SES sender and the ECS task-role permission, before enabling password-reset mail. The development sink is only intended for local SQLite and returns a development token.
- Use a private S3 bucket and signed downloads; never put media in a public bucket.
- Set `SQS_VISIBILITY_TIMEOUT_SECONDS` longer than the measured worst-case job, with a DLQ and bounded redelivery. Terraform defaults this to 3600 seconds and allows up to AWS's 12-hour maximum.
- Workers also extend the SQS visibility lease from their heartbeat while a message is actively processing; a crashed worker still leaves the message eligible for redelivery.
- Keep API and worker images separate. GPU capacity starts at zero and scales from queue depth in `infrastructure/terraform`.
- The API and worker containers run as the unprivileged `lingowave` user; the worker's model cache is under `XDG_CACHE_HOME` and local fallback data is explicitly owned by that user.
- Run `PYTHONPATH=backend python scripts/benchmarks/benchmark_providers.py <media>` against representative media whenever a provider or worker image changes. The checked-in `config/cost_profiles.json` contains measured internal credit rates from the real CPU acceptance/Chrome validation runs; update those values only with new evidence. The script reports missing providers as skipped; it never emits synthetic timings. Set `GPU_HOURLY_PRICE_USD`, `GPU_PRICING_SOURCE`, `AWS_INSTANCE_TYPE`, and `GPU_TYPE` in a cloud run when known; the JSON records those values plus detected NVIDIA VRAM and region without guessing.
- PostgreSQL deployments fail closed when an enabled credit profile is marked `measured=false`; do not enable `ALLOW_UNMEASURED_PRICING` for public traffic. Disabled capabilities, such as lip sync before a provider is installed, are excluded from the measured-profile gate and remain rejected before credit reservation.
- Google sign-in is optional and uses the existing LingoWave session cookie. In Google Cloud Console, configure an OAuth consent screen and a Web application client, then register the exact callback URI `https://<cloudfront-or-custom-domain>/api/auth/google/callback` (local development uses `http://localhost:8000/api/auth/google/callback`). Store `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_REDIRECT_URI` in AWS Secrets Manager and pass their ARNs through Terraform `api_secrets`; never commit client secrets. The backend verifies the Google OIDC token, issuer, nonce, and verified email, binds state to a short-lived HttpOnly browser cookie, stores only the provider subject/email identity, and never stores Google access or refresh tokens.
- Do not enable public voice cloning until consent, deletion, abuse reporting, and the model/checkpoint license review are complete.
- Use the operator endpoints and Operations view for queue depth, failed-job retry, abuse resolution, model-version/profile inventory, and credit adjustments. Workers publish short-lived leases while polling and processing; the active-worker count is the number of unexpired leases, so crashed workers naturally disappear after `WORKER_LEASE_SECONDS` (default 900). Estimated and actual compute cost are populated when a measured GPU profile matches `GPU_TYPE`/`AWS_REGION`, or when a CPU worker supplies a positive `COMPUTE_HOURLY_PRICE_USD`; otherwise the dashboard shows an em dash.
- Keep `DeepFilterNetNoiseProvider` on the default production path with a worker image that contains the pinned DeepFilterNet packages and native `libdf` dependency. `NOISE_REMOVAL_FALLBACK=ffmpeg-afftdn` is an explicit constrained-development fallback using FFmpeg's `afftdn` filter; do not enable it as a substitute for the production ML provider without a deliberate review.
- Users can retrieve their recent persisted processing telemetry from `GET /api/usage`; it includes operation/state, input/output duration and bytes, worker/model, retries, and estimated/actual compute cost.
- Stripe billing uses hosted Checkout for subscriptions and one-time credit packs, plus a customer portal. Webhooks must be delivered to `POST /api/billing/webhook` with the raw request body; event IDs, ledger references, and refund reversals are idempotent. Set `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, the six price IDs, and the success/cancel/portal URLs before enabling production checkout. Without them, billing endpoints return a safe configuration error and no simulated payment is accepted.
- Browser acceptance keeps authentication/UI coverage enabled by default; real CPU transcription and voice validation can run through the manual AWS CPU acceptance workflow, while GPU-scale acceptance still requires `E2E_GPU_ENABLED=true` and an authorized GPU runner with approved model caches. The public Free Tier environment intentionally keeps expensive model workflows disabled by default.
- Authentication, upload, job, synthesis, and expensive-operation limits use database-backed fixed windows so limits are shared across API replicas; plan-level concurrent-job and voice-profile quotas remain enforced from PostgreSQL state.
- Schedule `PYTHONPATH=backend python scripts/cleanup_retention.py --apply` after reviewing its default dry-run output. It tombstones expired media and voice references, removes expired generated artifact rows, clears stale job output pointers, and deletes their private objects; S3 lifecycle rules provide a second storage-side expiration guard.
- The default CI workflow covers API tests, migrations, Bandit/Ruff static checks, frontend build, API/CPU-worker Docker builds, Compose config, and Terraform validation. Real model timings use the manual `GPU provider benchmarks` workflow, which requires an approved self-hosted GPU runner and produces provider plus optional complete-dubbing machine-readable artifacts; blocked stages are recorded explicitly and never represented as successful benchmarks.

## Incident handling

For stuck jobs, inspect `/api/jobs/{id}` and the `job_events` sequence before changing state. The worker reconciles stale jobs across every active processing stage, requeues them within the bounded retry budget, and releases the reservation after the budget is exhausted. If a deployment needs immediate intervention, re-drive the SQS message or use operator retry; do not edit ledger rows manually. Rotate session secrets at the edge and revoke affected sessions if account access is suspected.
